# Execution reports

Reports are generated by the control plane from persisted records. Fetch one execution with its factory history, or factory history alone. History defaults to the previous 90 days; it does not depend on the selected CLI context.

```sh
factory report EXECUTION-ID > report.html
factory report --factory golang > factory-history.html
factory report EXECUTION-ID --from 2026-10-01 --to 2026-10-31 -o json > report.json
factory report --factory golang -o template > report-template.html
```

Dates are UTC midnight; timestamps accept RFC3339 offsets. The interval is **[from, to)**, selecting executions by creation time. `--to` must not be in the future. An explicitly selected execution is shown even outside the history interval. `--factory` with an execution must match that execution's factory name. An unambiguous execution ID prefix is accepted.

The JSON response contains `id`, `snapshot`, and `html`. Keep `id` to retrieve exactly the saved report, even after an execution or its accounting changes:

```sh
factory report --snapshot REPORT-ID > same-report.html
factory report --snapshot REPORT-ID -o json
```

A saved report cannot be combined with new factory, execution, or time selectors. Creating a report saves a new immutable record; it does not write files in the project. Shell redirection above is optional. The HTML is offline and includes its stylesheet.

## Organization and evidence

| Section | Contents |
|---|---|
| Summary | Selected execution, controller state, reported usage and wall time. |
| Measurements | Stage visits, step visits, per-attempt timings/failures, sessions and reported models. |
| History | All selected execution states, token chart, completion count and metric sample sizes. |
| Assessments | Agent results and operator decisions, attributed to their source. |
| Quality measures | Definitions and availability of automated checks. No fabricated scores. |
| Methodology | Snapshot identity, accounting rules and comparison limitations. |

Completed model responses are the measured counter; they are not whole agent assignments or workflow loop rounds. Token totals include input, cache read, cache write and output. Missing accounting is **unknown**, not zero. Cache tokens are not assumed free. Tool failures are counts; no failure rate is calculated without a completed-call denominator. Stage and step durations may overlap.

Tests, coverage, static-analysis findings and complexity need structured check evidence tied to a source revision and tool/configuration version. This report service does not yet collect those check measurements. Agent statements about them remain **assessments**, not measured check results. No judge model is invoked.

Factory averages describe operational history. The same factory name does not establish a comparable evaluation scenario. A controlled comparison must pin task/seed/fixtures, assessment protocol, rubric and accounting rules, identify configuration/model variants, and keep failures in the reliability denominator. The current generic report does not manufacture this identity or compute controlled benchmark scores.

## Persistence and determinism

The controller persists stage entries/exits, step visits, attempts, accepted results, and execution completion/failure/cancellation timestamps in Factory-owned PostgreSQL records, atomically with lifecycle events. Event replay preserves original lifecycle timestamps and results. Stage visits span loop rounds and human feedback inside that stage; step visits and attempt numbers are separate.

The report reads execution, session and telemetry records in one repeatable-read database transaction, projects report fields, renders its embedded versioned template and saves the snapshot and HTML under a SHA-256 content ID (including the embedded template digest). Configuration contents, environment values and workflow-engine identifiers are not exported. Agent assessment text and failure messages remain report content; normal secret-handling requirements still apply. HTML text is escaped.

Fetching a saved ID returns its stored snapshot and HTML. It does not reread changed artifacts, parse agent logs, inspect processes, or rerun agents, tests or judges. Historical records missing stage/attempt/terminal timestamps remain incomplete; the renderer does not infer those measurements from prose or `updated_at`.

## MCP access

Run the local operator MCP server over stdio:

```sh
factory mcp
```

Example MCP client configuration; `factory` must be on that client's PATH:

```json
{"mcpServers":{"factory":{"command":"factory","args":["mcp"]}}}
```

The `get_report` tool accepts `factory`, `execution_id`, `from`, `to`, `report_id`, and `format` (`json`, `html`, or `template`). MCP times are RFC3339 timestamps. For example:

```json
{"execution_id":"EXECUTION-ID","from":"2026-10-01T00:00:00Z","format":"json"}
```

Use `{"report_id":"REPORT-ID","format":"html"}` to retrieve a saved report, or `{"format":"template"}` to fetch the embedded template source. CLI and MCP call the same control-plane report API. This operator server is distinct from the participant-scoped agent messaging MCP server; workflow agents are not granted cross-execution report access.
